# 挪车提醒 · 设计说明

## 1. 目标与非目标

### 目标

- 在 Android 上后台接收短信，按用户自定义关键词匹配违停通知。
- 在办公室场景下做到“不打扰但不容易漏”：轻提醒 → 1 分钟 → 震动 → 1 分钟 → 闹钟。
- 所有处理在本机完成，不联网、不上传短信。
- 对系统权限、厂商后台限制有清晰的引导和降级路径。

### 非目标

- 不做真正的自动拨号语音提醒。Android 不允许第三方 App 自动拨号后向用户播放 TTS；只能模拟来电界面，且对办公室场景更打扰。
- 不做云端同步、远程查看、多设备管理。
- 不尝试绕过 Android 的强制停止、通知关闭、勿扰模式等用户/系统决定，只做合规的降级提示。

## 2. 组件关系

```
 SMS_RECEIVED (系统广播)
        │
        ▼
 ┌──────────────────┐      关键词/严格模式/营销过滤
 │  SmsReceiver     │──────┐
 └──────────────────┘      │
                           ▼
                  ┌──────────────────┐
                  │ KeywordMatcher   │  (纯 Kotlin，可单测)
                  └──────────────────┘
                           │ 命中
                           ▼
                  ┌──────────────────┐
                  │ AlertCoordinator │  状态机 / 去重 / 历史
                  └───────┬──────────┘
          ┌───────────────┼─────────────────┐
          ▼               ▼                 ▼
 ┌────────────────┐ ┌──────────────┐ ┌─────────────────┐
 │ Notification   │ │ AlertScheduler│ │  AlertService   │
 │ Helper         │ │ 精确闹钟      │ │ 震动/闹钟前台服务 │
 └───────┬────────┘ └──────┬───────┘ └────────┬────────┘
         │                 │                  │
         ▼                 ▼                  ▼
   轻提醒通知        EscalationReceiver    全屏 AlertActivity
   （横幅+短铃）      （60 秒后）           （锁屏可弹出）
                           │
                           ├─ GENTLE  → 震动阶段（无声音）
                           └─ VIBRATE → 闹钟阶段（系统闹钟铃声）
```

### 关键类

| 类 | 职责 |
|---|---|
| `SmsReceiver` | 接收 `SMS_RECEIVED`，拼接多段短信，读取发送方，调用匹配器 |
| `KeywordMatcher` | 归一化、关键词匹配、严格模式、营销短信过滤；无 Android 依赖 |
| `AlertCoordinator` | 唯一的状态机入口：新建提醒、升级、确认、稍后、静音、取消、开机恢复 |
| `AlertScheduler` | 用 `AlarmManager.setAlarmClock` 调度升级；无精确闹钟权限时降级为不精确闹钟 |
| `AlertService` | 分阶段前台服务：`specialUse` 震动阶段、`mediaPlayback` 闹钟阶段；播放系统闹钟铃声、渐强、震动、唤醒锁 |
| `AlertActivity` | 全屏提醒页；锁屏显示、亮屏、阶段倒计时、确认/稍后/停止震动或静音 |
| `NotificationHelper` | 通知频道、轻提醒/震动/闹钟/权限巡检通知、通知按钮 PendingIntent |
| `PermissionAudit` | 统一计算缺失的权限/自启动确认项，首页和每日巡检共用 |
| `PermissionCheckScheduler` | 计算并调度 09:00 / 18:00 的权限巡检 |
| `PermissionCheckReceiver` | 巡检权限、发提醒、重排下一次巡检、尝试恢复后台守护 |
| `GuardianService` | 可选 `specialUse` 前台服务，提高进程存活率 |
| `AppPrefs` | SharedPreferences + JSON；关键词、设置、自启动确认、待处理提醒、历史 |
| `MainActivity` | 只展示缺失权限、关键词、提醒设置、最近 3 条历史、测试 |

## 3. 提醒状态机

### 3.1 新建

`AlertCoordinator.onSmsMatched()`：

1. 若 2 分钟内收到相同“发送方 + 正文”，忽略（防多段短信/运营商重发）。
2. 若当前已有提醒在响/震动，仅写入历史并提示“又收到一条”，不打断当前提醒。
3. 根据提醒模式计算 `escalationAt`：
   - 渐进提醒：`now + 60s`，阶段 `GENTLE`
   - 直接闹钟：`now`，阶段 `ALARM`
   - 仅通知：`0`，阶段 `GENTLE`，不调度升级
4. 写入 `PendingAlert` 和历史记录。
5. 渐进提醒：发轻提醒 + 调度 60 秒后的精确闹钟；直接闹钟：启动 `AlertService`；仅通知：只发轻提醒。

### 3.2 第一级升级：震动

`EscalationReceiver`（60 秒后）→ `AlertCoordinator.escalate()`：

- 校验 `PendingAlert.id`，防止旧闹钟误触发新提醒。
- 若当前阶段是 `GENTLE`：阶段改为 `VIBRATE`，`escalationAt = now + 60s`，取消轻提醒，启动震动阶段。
- `AlertService` 以 `specialUse` 前台服务运行：全屏提醒页 + 约 12 秒强震动，不播放声音。
- 同时调度 60 秒后的下一次精确闹钟。

### 3.3 第二级升级：闹钟

60 秒后再次触发 `EscalationReceiver`：

- 当前阶段是 `VIBRATE`：阶段改为 `ALARM`，取消震动通知，启动闹钟阶段。
- `AlertService` 以 `mediaPlayback` 前台服务运行：系统默认闹钟铃声 + 震动 + 全屏闹钟页。
- `AlertService` 先 `startForeground`，再播放声音；即使全屏 Activity 被系统拦截，声音和通知仍然工作。

### 3.4 确认 / 稍后 / 停止

| 操作 | 效果 |
|---|---|
| 我已挪车 | 清空 pending、取消精确闹钟、停止服务、取消通知、历史标记“已确认” |
| 5 分钟后再提醒 | 保持同一个 pending id，更新 `escalationAt = now + 5min`，阶段设为 `ALARM`，安排下一次精确闹钟；历史标记“已稍后” |
| 停止震动 / 先静音 | 停止当前震动或声音，保留“待确认/等待响铃”通知；已安排的下一阶段仍然有效 |
| 取消稍后 | 只在“已稍后”状态通知上出现；清空 pending，历史标记“已取消” |

### 3.5 阶段超时

`AlertService` 在当前阶段时长结束后：

- 震动阶段：12 秒后停止震动，释放唤醒锁，发“震动已停止，将在 HH:mm 响铃”通知，服务停止；60 秒后的闹钟仍会触发。
- 闹钟阶段：`ringSeconds` 后停止声音/震动，发“未确认”通知，服务停止；pending 保留，用户仍可从通知确认或稍后。

### 3.6 开机恢复

`BootReceiver`：

- 若 `PendingAlert` 的 `escalationAt` 还在未来：重新调度，并显示“提醒已恢复”状态通知。
- 若已经过期：清空 pending，历史标记“已错过”，发一条“有一条未处理的提醒”通知。
- 若开启了后台守护，重新启动 `GuardianService`。

## 4. 提醒方式与参数

### 4.1 三段渐进（默认）

- 第一段：`NotificationChannel` 高优先级 + 自定义 2.8 秒轻柔 WAV + 一次震动；不设置 `setFullScreenIntent`，所以不抢屏。
- 第二段（60 秒后）：全屏提醒 + 约 12 秒强震动，不响铃；使用 `specialUse` 前台服务。
- 第三段（再 60 秒后）：全屏闹钟 + 系统闹钟铃声 + 震动 + 音量渐强；使用 `mediaPlayback` 前台服务。
- 目的：办公室先给一个不打扰的提示，再升级到无声但可感知的震动，最后才响铃。

### 4.2 声音

- 轻提醒：`res/raw/gentle_chime.wav`，两音轻柔提示，2.8 秒。
- 闹钟：默认读取 `RingtoneManager.getDefaultUri(TYPE_ALARM)`，即手机系统闹钟铃声；小米手机上就是 MIUI 时钟里设置的默认闹钟铃声。若读取失败，回退到内置 `res/raw/alarm_tone.wav`。
- 通过 `AudioAttributes.USAGE_ALARM` 走系统“闹钟”音量通道，而不是媒体音量。
- 音量渐强：从 20% 开始，每 800ms 增加 8%，约 8 秒到 100%。
- 不主动修改系统音量，避免侵入用户设置；检测到闹钟音量为 0 时，测试按钮会提示。

### 4.3 界面与权限展示

- 主界面只保留四块：状态 Hero、关键词、提醒方式、最近记录。
- Hero 使用深青渐变 + 白色状态图标 + 白色守护开关；只有“未开启”的权限才会出现在下方“完善运行设置”卡片里，全部开启后整张卡片隐藏。
- 权限项每行都是“未开启”状态，不再显示绿色的“已开启”行；用户开启后下一次 `onResume` 即消失。
- 厂商自启动/后台弹出入口收进右上角菜单，不占用主界面。
- 历史默认只展示 3 条，点“查看全部”展开，避免首页过长。
- 提醒方式用三枚分段按钮代替单选框，减少视觉噪音；等待时间固定为 1 分钟，不再提供滑杆。

### 4.4 权限巡检与自启动

- `PermissionAudit` 统一判断短信、通知、精确闹钟、全屏提醒、电池白名单和自启动确认。
- `PermissionCheckScheduler` 在每天 09:00 / 18:00 调度一次巡检；优先使用 `setExactAndAllowWhileIdle`，没有精确闹钟权限时降级为不精确闹钟。
- 巡检完成后由 `PermissionCheckReceiver` 重排下一次；时区/时间变化和开机时由 `BootReceiver` 重排。
- 有缺失时发“挪车提醒需要设置”通知；全部满足时取消旧提醒。
- 自启动没有公开读取 API，因此采用“打开厂商设置 → 返回后确认已开启”的本地确认流程，确认结果只存储在本机。
- 关闭后台守护时，首页 Hero 从青绿色切换为棕褐色，显示“守卫已关闭”，开关下方显示“点击开启”，从视觉上明确区分。
- 巡检时会尝试重新启动用户已开启的后台守护服务；若被系统限制则静默失败。

### 4.5 为什么不用系统闹钟 / 电话

- 系统时钟 App 没有对外 API 让三方 App“立即响铃”。`AlarmClock.ACTION_SET_ALARM` 只能打开时钟 App 的创建界面，并且是未来时间。
- 本 App 用 `AlarmManager.setAlarmClock()` 实现“系统级精确闹钟”的调度语义（系统会显示闹钟图标、可在 Doze 下准时触发），但响铃由自己的前台服务播放系统默认闹钟铃声。
- 真电话需要 `ACTION_CALL` 走运营商通话，对方听到的是你，不是 TTS；自动播放语音在 Android 上不可行。
- 模拟来电（全屏来电 UI）技术上可行，但 Android 14+ 对全屏 Intent 有额外限制，且办公室场景容易被同事误以为真来电。本版不实现，保留为未来可选项。

## 5. 关键词匹配

### 5.1 归一化

1. `Normalizer.NFKC`：全角字母/数字/标点转半角；
2. 去除零宽字符（U+200B–U+200D、U+FEFF）；
3. 去除所有空白；
4. 转小写（对中文无影响，对英文关键词有效）。

### 5.2 匹配

- 默认：任一关键词是归一化正文的子串，即命中。
- 严格模式：不同关键词命中数 ≥ 2。
- 关键词先去重（按归一化值），避免重复关键词在严格模式下被重复计数。
- 空关键词列表不会触发。

### 5.3 营销过滤

正文包含以下任一标记时忽略（可关闭）：

- `退订`
- `回复td`
- `回t退订`
- `拒收`
- `unsubscribe`

不使用“贷款 / 优惠 / 促销”等内容词过滤，因为真实违停短信也可能包含“如有疑问请忽略”，过度过滤会漏报。用户还可以开启严格模式进一步降低误报。

## 6. 权限与降级

| 能力 | 未授权时的行为 |
|---|---|
| 短信权限 | 收不到广播；主页只显示这一项缺失，点击直接去授权 |
| 通知权限 | 通知/FULL_SCREEN 不显示；前台服务仍可能播放声音，但用户看不到页面 |
| 精确闹钟 | 降级为 `setAndAllowWhileIdle`，可能延迟；主页只显示缺失项 |
| 全屏提醒 | 通知仍为高优先级并带全屏 Intent，但系统可能只显示横幅；声音由服务播放 |
| 电池白名单 | 可能被息屏冻结；主页只显示缺失项 |
| 勿扰访问 | 免打扰开关不生效；即使授权，部分系统仍会拦截闹钟声道 |
| 自启动/后台弹出 | 厂商可能拦截；入口在右上角菜单“设置后台权限” |

**界面上的权限展示规则**：每项权限只在“未开启”时出现；一旦开启，下一次 `onResume` 刷新时该行立即消失；全部开启后整个“完善运行设置”卡片隐藏。这样主界面只剩状态、关键词、提醒方式和最近记录。

### 前台服务启动限制

- 升级由 `AlarmManager` 的精确闹钟广播触发，属于 Android 12+ 前台服务启动限制的豁免场景。
- 直接闹钟模式从短信广播直接启动前台服务，若被系统拒绝，`AlertCoordinator` 会降级为带全屏 Intent 的高优先级通知。
- `GuardianService` 只在 App 可见或开机广播时启动，避免后台启动限制。

## 7. 数据与隐私

### 7.1 存储

`SharedPreferences` 文件：`parking_alert_prefs.xml`。

| Key | 内容 |
|---|---|
| `keywords` | JSON 数组 |
| `alert_mode` / `ring_seconds` | 提醒参数（两段等待时间固定为 60 秒） |
| `strict_mode` / `ignore_marketing` | 匹配参数 |
| `volume_ramp` / `vibrate` / `bypass_dnd` | 声音参数 |
| `guardian_enabled` / `save_history` | 后台与隐私开关 |
| `pending_alert` | 当前待处理提醒（JSON） |
| `history` | 最近 50 条（JSON 数组） |
| `last_sms_hash` / `last_sms_at` | 2 分钟去重 |

### 7.2 备份

`backup_rules.xml` 和 `data_extraction_rules.xml` 均排除了该 SharedPreferences 文件，避免短信内容进入云备份或设备迁移。

### 7.3 网络

Manifest 中没有 `INTERNET` 权限，代码中没有网络调用。

### 7.4 锁屏可见性

通知频道使用 `VISIBILITY_PUBLIC`，锁屏会显示短信正文。用户可在系统通知设置中改为隐藏。`AlertActivity` 使用 `showWhenLocked`，这是闹钟类应用的预期行为。

## 8. 可靠性取舍

| 选择 | 原因 | 代价 |
|---|---|---|
| 系统短信广播而不是轮询 | 系统在收到短信时唤醒 App，省电且实时 | 依赖 App 未被强制停止、未被安全软件拦截 |
| 三段式而不是立即全屏 | 办公室友好，先轻后重 | 极端情况下 60 秒内可能没注意到第一段 |
| 精确闹钟 + 前台服务 | 锁屏/Doze 下更可靠 | 需要额外权限；部分厂商仍可能拦截 |
| 常驻前台服务（可选） | 提升进程存活率 | 多一条常驻通知，增加耗电 |
| 全屏 Intent | 锁屏时能直接看到 | Android 14+ 需要用户授权，可能退化为横幅 |
| 音量渐强 | 不突然吓到同事 | 前几秒声音较小，极端情况下可能错过 |
| 本地存储、不联网 | 隐私最好 | 换机/清数据后记录不保留 |

## 9. 测试矩阵

### 已执行

- `KeywordMatcherTest`：9 个用例，覆盖默认匹配、严格模式、营销过滤、全角/空白/零宽归一化、英文大小写、重复关键词、空列表、真实测试文案。
- `LayoutSmokeTest`：2 个 Robolectric 用例，在主界面主题下 inflate `activity_main` 并验证分段按钮可选中，在闹钟主题下 inflate `activity_alert`。
- `PermissionCheckTimesTest`：4 个用例，覆盖 08:59、09:00、12:30、18:00、23:59 的下一次巡检时间。
- `assembleDebug` / `assembleRelease`：编译通过。
- `lintDebug` / `lintVitalRelease`：执行并通过。
- APK 清单检查：包名、min/target SDK、权限、组件、前台服务类型。
- `apksigner verify`：release APK 签名校验。
- 音频资源生成：2.8 秒轻提示、6 秒回退警报。
- 系统闹钟铃声：通过 `RingtoneManager.TYPE_ALARM` 读取，失败时回退内置音频。

### 需要在真机补测

- 安装与首次权限引导（Android 8 / 13 / 14 / 15）。
- 真实短信到达 → 轻提醒 → 60 秒震动 → 再 60 秒闹钟。
- 锁屏、息屏、勿扰模式下的表现。
- 小米/华为/OPPO/vivo 的自启动与后台弹出设置。
- 强制停止、重启、清理后台后的恢复行为。
- 通知频道关闭、精确闹钟关闭、全屏提醒关闭时的降级路径。
